# Portfolio Home

## Scope and mode

- Target: `src/App.tsx`, with `index.html` as the document boundary.
- Visitor mode: Experience.
- Audience: engineering leaders, hiring managers, senior engineers, and technical collaborators.
- Job: understand Hatim's engineering range and ownership in seconds, then explore verified work chronologically and make contact.

## Direction

- World: **The Event Recorder** - a modern scientific event chamber and long-exposure run log where software projects appear as recorded collisions, trajectories, and system layers.
- Approved comp: `.impeccable/mocks/event-recorder-chamber.png`.
- Approval: delegated by the user's explicit full creative freedom. The central chamber was selected because it makes real contribution evidence structural, creates the strongest first-viewport memory, and opens naturally into a chronological work sequence.
- Palette strategy: committed ultramarine field with hot signal orange, bone white, deep ink, and sparse chartreuse measurement ticks.
- Memorable moment: the contribution field reacts to pointer position and scroll while the name, verified stats, and work action stay legible and fixed in the same composition.
- Do not literalize: the comp's invented project names, fake system readouts, bogus engineering years, or fabricated impact metrics.

## Sequence

1. Event chamber first viewport: name, positioning, verified GitHub snapshot, and primary route into work.
2. UnifyApps evidence: workstreams and code-path concentration displayed as an annotated platform map, followed by Salesforce.
3. Project chronology: serious public and private products first, then an older-work archive; newest creation date first.
4. Contribution signal: one-year monthly intensity and verified activity/streak facts.
5. Technical practice: compact capability bands derived from shipped work, not a floating badge cloud.
6. Contact close: resume, email, GitHub, LinkedIn, and LeetCode.

## Component grammar

- Corners: square; no pills except tiny factual status tags with near-square 2px corners.
- Lines: 1px bone/blue plot lines; 3-6px orange selection/axis accents.
- Elevation: none. Depth comes from overlap, field density, and color planes.
- Type: Clash Display at extreme scale for identity; system monospace for data; Clash regular for readable prose.
- Controls: hard rectangular blocks, visible focus inset, direct verb labels.
- Motion: one orchestrated chamber field plus section reveals; no scattered hover bobbing.

## Responsive and state constraints

- Desktop keeps the chamber off-center; mobile turns it into a cropped upper field behind the name and places verified readouts in a two-column grid.
- All projects remain accessible and chronological on small screens.
- Private projects have no dead repository links.
- Pointer effects disable on coarse pointers; all motion respects `prefers-reduced-motion`.
- No content is hidden behind animation; the page is fully readable before JavaScript motion starts.
